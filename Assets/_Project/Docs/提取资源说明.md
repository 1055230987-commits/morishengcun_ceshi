## 放在哪、为什么

投放位置是**按本工程既有约定推断**的，不是我另立一套：

| 提取类别 | 放到了 | 依据 |
|---|---|---|
| 石头矿物 | `_Project/Art/Environment/Props/Rocks/` | `Environment/Props/` 已存在且在 `Materials/` 里已有 `M_Rock.mat`；按类型再分一层是本工程既有做法（`Vegetation/Materials/` 下已分树冠/树干/草） |
| 木头林木、植物纤维 | `_Project/Art/Environment/Vegetation/` | 该目录已存在，已有树冠/树叶/树干/草材质 |
| 容器、载具、家具、武器 | `_Project/Art/Environment/Props/<各自子目录>/` | 同 Props 约定 |
| 建筑构件 | `_Project/Art/Environment/Buildings/` | 该目录已存在 |
| 角色生物 | `_Project/Art/Characters/`（**新建**） | 工程原本没有角色美术目录；角色不属于 Environment，故在 `Art/` 下平行新建，而不是塞进 `Environment/` |
| 贴图 | `_Project/Art/Textures/Extracted/`（**新建**） | 工程原本只有 `Art/VFX/Textures/`，是 VFX 专用；这批是通用贴图库，故在 `Art/Textures/` 下新建 |
| 编辑器工具 | `_Project/Editor/EnvironmentTools/` | 该目录已存在，且 `Game.Editor.asmdef` 覆盖它 |

## 命名规则

```
<网格名>_<来源bundle前12位>_<pathID低24位>.fbx
例：stone_chunk_2_c6a7fb0a8c6c_157e6e.fbx
```

后缀保证全局唯一（原包里不同关卡的网格会重名）；想按原名找，用 `提取模型索引.csv` 的「模型名」列筛。

## 怎么用

1. **几何与 UV 是完整的**，直接拖进场景即可。
2. **材质与贴图没有随 FBX 导入。** 原因见下节。贴图已在 `_Project/Art/Textures/Extracted/`，用菜单 `Tools ▸ 末日生存 ▸ 提取资源贴图匹配…` 按名字相似度批量挂贴图，或自己建材质。
3. **索引**：`提取模型索引.csv` 可用 Excel 筛选（模型名 / 目录 / 顶点数 / 是否带 UV）。

## 材质与贴图为什么没自动挂上

这个 APK 被 **BNDLTOOL 重打包**过（`META-INF/BNDLTOOL.SF`），`m_FileID → m_Externals` 的对应关系已失效。表现为：模型几何在包内自洽（所以能完整导出），但材质引用指向的依赖包里往往只有一两个无关对象，无法可靠解析。

同源问题也导致**关卡摆位无法还原** —— 那些网格与场景对象的对应关系已经不可靠，所以本批交付的是**素材本身**，不含场景摆位。

## 已知限制

1. **不含场景摆位**（每个 FBX 是局部坐标的独立素材）
2. **不含骨骼动画**、Shader、LOD 层级
3. **分类是关键词启发式**，有噪音。实测误判例：
   - `MercenaryShotgunNPC` 含 `shotgun` → 进了武器类，其实是 NPC
   - `Armor_Locomotive_Coop_Decor` 含 `armor` → 进了武器类，其实是火车装饰
   - `ManLumberjack_Torso` 含 `lumber` → 进了木头类，其实是角色部件
   - `CaveGrove_Fox` 含树名 → 进了木头类，其实是狐狸
   需要精确筛选请查 CSV。
4. **顶点色**：部分网格带顶点色，已写入 FBX（`LayerElementColor`），但 Unity 默认不导入顶点色，需要在模型导入设置里勾选。
5. 三角形数上限 30,000：更大的关卡合批网格（`Location_*`、`Baked_Optimized_*`）未导出。
