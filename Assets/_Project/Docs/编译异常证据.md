# 编译异常证据留档

> 用途：`Assembly-CSharp-Editor` 找不到 `Assembly-CSharp` 运行时类型的**原始证据**。
> 审阅意见指出：这种现象**不是"没有 asmdef"的正常结果**（默认预定义程序集体系下，Editor 程序集本应能引用 Runtime 程序集），
> 所以真正原因需要保留证据另行排查。
>
> 证据来源：`%LOCALAPPDATA%\Unity\Editor\Editor.log`（Unity 6.0.3.10f1）。
> 日志行号为原始 Editor.log 的行号。

---

## 2. 伴随异常：GUID 冲突（Editor.log 5188）

```
GUID [4f99328b6ccf3d541b310ce88e80533f] for asset 'Assets/Game/Camera/CameraRigDebugInfo.cs' conflicts with:
  'Assets/Game/Camera/CameraScreenAligner.cs' (current owner)
```

背景：`CameraScreenAligner.cs` 被重命名为 `CameraRigDebugInfo.cs`（内容相同，改了类名）。
两个 `.cs` 文件曾短时**同时存在**，并因为 `.meta` 手工写法与 Unity 生成方式相互覆盖，出现了同一 GUID 被两个资产占用。

**这条异常可能与第 1 条有关联**：GUID 冲突会让 Unity 的资产数据库（AssetDatabase）处于不一致状态，
而 `Assembly-CSharp-Editor` 的**类型解析依赖资产数据库的脚本映射**。
换句话说，"Editor 程序集找不到 Runtime 类型"有可能是 **AssetDatabase 脚本映射损坏**的表现，而不是 asmdef 缺失。

（“`.meta` 手工生成 + Unity 同时写 `.meta`” 这个操作在本工程中确实发生过多次，
已观察到 Unity 会把自己生成的 2 行 `.meta` 改写覆盖回来的现象。这是需要避免的操作方式。）

## 3. 现象汇总与推断

| 观察 | 是否与"缺 asmdef"一致 |
|---|---|
| 运行时程序集编译成功，编辑器程序集找不到其类型 | ⚠️ 部分。默认体系下 Editor 应能引用 Runtime |
| 报错类型会"漂移"（换掉一个又报另一个） | ⚠️ 更像是"整个类型可见性/映射出问题" |
| 文件移出 Editor 文件夹后，**同一程序集内**仍报找不到类型 | ❌ **完全不一致**。说明不只是程序集边界问题 |
| 伴随 GUID 冲突记录 | ⚠️ 指向 AssetDatabase 状态异常 |

### 候选原因（未验证，按可能性排序）

1. **AssetDatabase / 编译缓存（`Library/Bee`）处于损坏或不一致状态**
   —— 与“同程序集内找不到类型”最吻合
2. **GUID 冲突导致的脚本映射损坏**（见第 2 节）
3. Unity 6000.3.10f1 的增量编译（Bee）在此工程上的已知缺陷
4. 本机环境问题（沙箱、路径含非 ASCII 字符 `末日生存`）—— 但 C# 编译本身正常，可能性较低

### 已采取的应对（P0）

- 建立了 `Game.Runtime` / `Game.Editor` 两个 asmdef，把 Editor 工具真正移回 `Editor/` 程序集
  —— 无论原因为何，**这是正确的结构**，且能排除"程序集边界"这一维度的干扰
- 运行时代码不再依赖全限定名绕过问题，恢复了正常的 `using` 写法

### 建议的后续排查步骤（如果问题复现）

1. 完全关闭 Unity，删除 `Library/Bee` 与 `Library/ScriptAssemblies`，重开
2. 检查 Project 窗口是否有 "Multiple assets have the same GUID" 警告
3. 若仍复现，用 `Library/Bee/artifacts/*/Assembly-CSharp-Editor.rsp` 对比 `-r:` 里是否真的列了 `Assembly-CSharp.dll`
   （本次已确认 `.rsp` 机制可用于独立复现编译，见下）

## 4. 附：独立编译复现方法（本次排查中发现，可复用）

Unity 会把完整编译命令行写入响应文件：

```
Library/Bee/artifacts/1900b0aE.dag/Assembly-CSharp.rsp      ← 全部引用/define/源文件
Library/Bee/artifacts/1900b0aE.dag/Assembly-CSharp.rsp2     ← 附加源文件（本工程为空）
```

可以用 Unity 自带的 Roslyn 重放它，**不需要启动第二个 Unity 实例**：

```powershell
$csc = "E:\unity\untiy Editor\6000.3.10f1\Editor\Data\DotNetSdkRoslyn\csc.dll"
$dotnet = "E:\unity\untiy Editor\6000.3.10f1\Editor\Data\NetCoreRuntime\dotnet.exe"
# 去掉 -out / -refout 并改成临时路径，避免覆盖 Unity 的构件
& $dotnet exec $csc /nostdlib /noconfig /shared "@check.rsp" "-out:$env:TEMP\check.dll"
```

**注意（本次踩到的坑）**：`.rsp` 里的源文件列表是 **Unity 生成时的快照**，
如果新增了 `.cs` 但 Unity 还没 reimport，`.rsp` 里就**没有**这些文件，
会导致"明明写了却报找不到类型"的**误报**。用它验证前应先对比 `Assets/` 下实际存在的 `.cs` 并补齐。
