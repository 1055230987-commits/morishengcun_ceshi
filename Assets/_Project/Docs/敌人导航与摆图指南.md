# 敌人导航与手工摆图指南

更新：2026-10-19。适用：Unity 6000.3.10f1 / AI Navigation 2.0.10。

## 当前怎么工作

敌人的状态机负责巡逻、追击和攻击；NavMesh 负责路线；CharacterController 负责碰撞、重力和实际位移。不要再给当前敌人额外添加一个自动移动的 NavMeshAgent，否则两套移动可能互相干扰。

有同层导航网格时使用路径跟随；没有网格时才回退到局部探距。目标没有可达路径时等待重试，不把“无路”“部分路径末端”“到达”混为一谈，也不靠探距继续撞墙。

当前感知使用以敌人为中心的 360° 水平圆形仇恨范围，默认半径 14 米，离开范围后保留 3 秒追击。不是完整的潜行/听觉系统；伤害另外检查楼层与实际遮挡。隔墙发现目标与隔墙造成伤害是两件事。

## 每次摆地图的操作顺序

1. 退出 Play，打开你实际要玩的场景。先给新场景命名并保存。
2. 摆地面、建筑、墙、楼板、楼梯，检查它们有实际碰撞体。静态建筑可用合理的 BoxCollider 或 MeshCollider；地形使用 TerrainCollider。
3. 通道和楼梯先按真实人物体积留空间，再考虑视觉效果。装饰模型不能代替碰撞检查。
4. 放敌人和巡逻路点。敌人脚底放在地面上，不能埋墙、卡在柱子里或悬空。路点也放在同一条真正能走的路上。
5. 执行「游戏 → 工程 → 烘焙敌人导航网格」。默认工具只烘当前活动场景，使用物理碰撞体，并临时排除角色。它会建立专用 SurvivalEnemy 类型，以场景敌人的碰撞尺寸和较保守的通行能力烘焙，不覆盖 Humanoid。
6. 执行「游戏 → 工程 → 诊断导航网格（只读）」。检查导航资产已持久化、出生点通过、到玩家和巡逻点显示 PathComplete。PathPartial 表示只能走一部分；采样成功不代表两个区域连通。
7. Scene 视图打开导航显示，逐层检查蓝色区域，特别看门口、墙角、楼梯上下口。只有屋顶蓝了、室内没蓝，不算完成。
8. Ctrl+S 保存场景。烘焙生成的导航 .asset、.meta 与场景都需要加入 Git。
9. Play 实测；不要只看蓝色网格。最后退出 Play，关闭重开场景，再确认导航资产与路线依然存在。

**不需要点「重建到当前场景」。** 那是灰盒生成器，会影响手工布局；烘焙导航是另一件事。

## 哪些改动需要重新烘焙

| 改动 | 怎么处理 |
|---|---|
| 只改材质、灯光、天空、后期或非碰撞装饰 | 通常不需要烘焙 |
| 移动墙、房子、树石等实际阻挡物，修改地形、碰撞体、楼梯或楼板 | 重新烘焙 |
| 只移动敌人或巡逻路点，地形未改 | 先诊断落点和连通性，通常不用重新烘焙 |
| 修改敌人半径、身高、台阶或坡度能力 | 重新烘焙并运行诊断 |
| 运行时通过当前建造系统新建墙 | 已自动添加 Carving 障碍，不需要编辑器重新烘焙；生效后等待下一次路径重算 |
| 运行时建出新楼板、楼梯或桥 | 当前不会自动产生可走的导航面，需要后续区域更新功能 |

## 门、楼梯和多层建筑

- 当前灰盒敌人通常半径 0.35 米、身高 1.8 米、最大台阶 0.4 米、坡度上限 50 度；实际以 Inspector 为准。门宽建议先留 1.0—1.2 米以上，头顶净空先留约 2.1 米，再实测收窄。
- 检查的是碰撞体之间的净宽，不只是看到的门框宽度。不要让隐藏的楼板或大包围盒堵住门口和楼梯井。
- 楼梯必须存在物理连续的路线。单级高度应低于控制器台阶上限，楼梯上端不能被二楼板封死。可考虑用可行走斜坡碰撞体配合台阶外观，但需要检查坡度和贴地行为。
- 修改已摆好的楼梯后重新烘焙，分别测试上楼和下楼。
- 不要为了让敌人上楼而盲目扩大 SnapRadius。当前查询保留真实目标高度，并限制采样高度差，防止把二楼玩家投影到一楼。
- 当前 CharacterController 跟随器不实现跳跃、攀爬、电梯或断桥穿越。放一个 NavMeshLink 不会自动获得这些动作；目前先保证连续楼梯/坡道能走通。
- 普通静态墙直接参与烘焙。会在游戏过程中开关/移动的门，才考虑 NavMeshObstacle + Carving；门打开时碰撞体和障碍状态需要一起切换。当前没有自动门控制功能。
- Obstacle 的 Center/Size 是物体局部坐标，不能把世界尺寸再乘一次已有缩放。静止墙默认等待 0.05 秒后 Carving，再等待约 0.35 秒以内的常规路径重算；不是同帧承诺。

## 放敌人和巡逻点

优先复用已经能工作的敌人根对象，保持根节点缩放为 (1,1,1)，只缩放外观子节点。检查根上有 EnemyController 和 CharacterController，外观不要再叠加实体碰撞体。

复制灰盒敌人时，注意根及外观子节点上的 WorldObjectId 不能与原对象重复。新对象使用新的稳定前缀，例如 map01/enemy/004/body；不要为了消除重复去重写已有存档对象的 ID。执行「游戏 → 工程 → 校验当前场景 ID」。

巡逻点使用空物体，拖到 EnemyController 的 Patrol Points 数组。复制敌人后检查路点引用是否仍指向原敌人的路线；没有路点的敌人可以待机，发现玩家后再追击。

旧场景缺少导航配置时，Awake 会按配置版本迁移。若要显式写入默认值，可用「给场景敌人写入默认配置」，但它会覆盖当前避障参数；已经手调过参数时优先用只读诊断，不必反复重置。

## 必做的 Play 验收

| 用例 | 正常现象 |
|---|---|
| 开阔地发现玩家 | 追击，接近后攻击，不在玩家身边无故绕开 |
| 玩家藏在长墙另一侧 | 沿可达路线绕到墙端，不持续顶墙 |
| 隔着薄墙，双方距离很近 | 不隔墙扣血，仍然请求绕路 |
| C 形障碍和两栋房子之间 | 能沿路径走出，不长期原地换方向 |
| 多个敌人同时追击 | 有分离反应；窄门拥堵仍需实际调试，分离不等于完整人群交通系统 |
| 玩家上下楼 | 导航目标高度正确；不上不通的楼梯，不从楼下打到楼上 |
| 玩家新建、拆掉一面墙 | 等待 Carving 与重算后改道或恢复；封死全部出口时允许停在可达区域 |
| 保存、关闭、重开场景 | 导航资产仍存在，原来可走的路仍然可走 |

可以先执行「游戏 → 工程 → 验证敌人导航（独立测试场景）」检查真实 NavMesh 和控制器基本链路。该测试创建并关闭附加场景，不保存或替换当前地图；当前场景必须已经命名。结果写在 OptimizationReview/navigation-results.txt。

独立测试通过不能代替当前手工地图的 Play 验证，尤其是特殊楼梯、Carving 时序、拥堵与帧率表现。

## 圆形仇恨与主角死亡（2026-10-19）

- 敌人先查找场景中的存活 PlayerHealth，再按水平距离判断是否进入 Aggro Radius。现在不再需要敌人面朝玩家；攻击仍受墙体和楼层限制。
- 在 EnemyController 的「圆形仇恨范围」中修改 Aggro Radius（默认 14 米）。Show Aggro Range 控制可视圈：游戏中使用实际渲染的范围线，Scene 窗口使用 Gizmo；待机时橙黄，追击时游戏内变红，敌人死亡后隐藏。
- 范围圈跟随正在移动的敌人，不是以出生点为中心的活动边界。主角离开圆圈后默认还有 3 秒追击宽限；再次进入会续上仇恨。受击反击规则保留。
- 可视圈是调试显示，默认开启；需要干净画面时关闭 Show Aggro Range。不会改变碰撞，也不参与导航烘焙。
- 主角死亡后显示全屏黑色背景与「复活」按钮，关闭背包和建造，禁止移动、开枪和交互；鼠标释放以便点击按钮。死亡后敌人清除对主角的旧仇恨。
- 点击复活返回本次开局位置，回满血，默认保护 3 秒；不清空背包，不重载或重建世界。
- 已有 PlayerHealth 的旧场景会在运行时自动接入 PlayerDeathScreen，无需重建灰盒。若需要指定复活点，可在编辑模式给主角添加 PlayerDeathScreen，将一个空物体拖入 Respawn Point 后保存；留空则使用开局位置。
- 可在 Play 中用主角已有的 H 调试伤害键反复扣血验证死亡，连续按键需留出受伤无敌时间；也可正常让敌人击杀。检查死亡后按 B/Tab 不会打开其他模式，再点击复活。
- 独立原生检查菜单：「游戏 → 工程 → 验证圆形仇恨与死亡复活（独立测试场景）」。实际黑屏布局、鼠标点击与范围圈遮挡效果还需在 Game 窗口目视验收。
